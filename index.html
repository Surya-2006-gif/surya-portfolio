about

What I'm actually doing.

My starting point is usually someone else's paper. I'll reproduce it, get it working, then start pulling at the parts that feel hand-wavy — the assumptions that were never tested, the design choices that got justified post-hoc. A lot of my CV work came out of that: combining pieces from several papers into something that handles the cases the originals quietly ignored.

But the question I keep circling back to isn't "does this model work?" — it's "what did it actually learn?" That's what drew me to mechanistic interpretability. I want to crack open the weights and figure out what computation is really happening in there, independent of whatever task the model was trained on. Weight-space methods are what interest me most right now — the idea that you can read a model's circuits straight from its parameters, without needing activations at all.

That feels like the harder, more honest version of the question. I'm trying to work on it properly.

Orthogonal Low-Rank Decomposition of Weight Matrices
PyTorch
50-feature superposition toy model · GPT-2 Medium
  • Started from a simple question: if a model stores multiple features in a single weight matrix through superposition, can you decompose that back out directly from the weights?
  • Built a framework that factorizes the matrix into orthogonal, low-rank, feature-specific components — recovering representations for individual features without touching activations.
  • Validated against a 50-feature toy model with high-fidelity reconstruction, then ran it on GPT-2 Medium — worked cleanly there too, which was the real test.

Reverse-Engineering a Transformer Parity Checker
PyTorch
−51% accuracy after ablation
  • Trained a 2-layer transformer to compute parity, then traced exactly how it does it — not just that it works.
  • Layer 1 attention gives roughly uniform scores across all positions, gathering a summary of the bits seen so far. The 0 and 1 token vectors are technically linearly separable at this point, but variance in the 1-cluster causes accuracy to drop.
  • Layer 1's MLP fixes that: it reshapes the representations so 0 and 1 vectors become perfectly linearly separable and carries a clean linear parity signal forward to each token position.
  • Layer 2 attention uses a block-pattern with scores increasing slightly leftward — not computing parity itself (that's a non-linear operation), but formatting the vectors exactly the way Layer 2's MLP needs them.
  • Confirmed this causally: skipping Layer 2 attention and passing Layer 1 MLP output straight to the unembedding gives only ~50% accuracy. Swapping the learned block-pattern attention for uniform attention loses 51% — a clean story about what each component is actually doing.

Detachable-DETR: Encoder-Only Object Detection
PyTorch
0.57 mAP@0.5 · 15% faster
  • Wanted to see how much of DETR's capability lives in the encoder — so I dropped the decoder entirely and built detection on top of the encoder alone.
  • Added a dual-level denoising mechanism to compensate for the lost multi-scale context the decoder usually provides.
  • Ended up 15% faster with 0.57 mAP@0.5 / 0.43 mAP@0.5:0.95 on PASCAL VOC. Not state of the art, but the point was to see where the encoder's ceiling actually is.
Context-Aware YOLO with Modern Hopfield Networks
PyTorch · YOLO · OpenCV
66% of test cases flagged
  • Standard detectors will happily tell you there's a surfboard in a kitchen. I wanted to add some kind of scene-level memory so the model could flag when an object just doesn't fit its context.
  • Wired a Modern Hopfield Network into a YOLO detector, built and annotated a 1,000-image dataset, and evaluated it on contextual consistency rather than just detection accuracy.
  • Flagged semantically odd object–scene relationships in 66% of test cases. Rough, but it shows the idea has legs.
